## 1. 目的と概要
- 目的: 自分の生活リズムを整える。
- 概要: キャラの状態に合わせることで自分の生活リズムを整えるゲーム。まず理想の生活リズムを登録する。キャラは一日の中で、登録された生活リズムどおりに生活する。ユーザーの記録が目標からずれるとキャラの状態が変わり（例: 食事を抜く → 空腹になり、食事を勧める）、ユーザーはキャラに合わせて生活するようになる。
- キャラの役割【仮】: 次の 2 つを両方持たせる。
  1. **鏡**: ユーザーの記録・計測中のタイマーを反映して状態が変わる（睡眠中・勉強中・汗汗・空腹）。
  2. **ペースメーカー**: 目標の時刻（就寝・食事）が近づく／過ぎると、ホームの吹き出しで行動を促す（例:「そろそろ寝る時間だよ」）。状態そのものは変えない。

## 2. 記録する項目（設定項目）
| # | 項目 | 目標の設定 | 記録のしかた |
|---|---|---|---|
| 1 | 睡眠 | 「時間」（例 7時間）または「時間帯」（例 0:00〜7:00）を選んで設定 | ホームの「就寝」ボタンを押すと開始し、ボタンが「起床」に変わる。「起床」を押すと終了し、`睡眠時間 = 起床日時 − 就寝日時` で計算する。**睡眠専用の画面・手動入力はない** |
| 2 | 食事 | カロリー・たんぱく質・脂質・炭水化物の 1 日目標。初期値は年齢・性別から自動設定（`nutrition_standards`。性別が未回答・その他のときは男女の平均値）。食事時刻（朝・昼・夕）は初期値 **7:00／12:00／19:00**、目標変更画面で変更できる | 1 食ずつ記録（内容・区分・時間・栄養値・写真・コメント） |
| 3 | 運動 | やることをタスクとして複数登録（例: 1キロ走る／腕立て100回）。1 件以上必須【仮】 | 運動画面のチェックリストで毎日チェック。任意で移動距離を手入力。**運動タイマーはない** |
| 4 | ワーク | 1 日の目標ワーク時間（画面上の「学習時間」） | ホームの「ワーク開始」ボタンを押すと開始し、ボタンが「ワーク終了」に変わる。「ワーク終了」を押すと終了し、時間を計算する。**ワーク専用の画面・手動入力はない** |
| 5 | 自由設定（入浴・趣味など） | **今回の範囲外【仮】**（DB設計書で保留）。ホームのボタンは表示するが「準備中」 | — |

用語の統一: 画面・コードでは「ワーク」に統一する（画面資料の「仕事」「学習時間」「学習」タブも同じものを指す）。キャラ状態名は「勉強中」のまま。運動の目標欄の見出しは「運動」（資料の「運動時間」ではない）。

### 2.1 睡眠・ワークのタイマーの決まり
- 開始日時・終了日時はサーバーの時刻で保存する（ページを閉じても計測は続く）。
- **押し間違いの取り消し（強制リセット）**: 計測中はホームに「取り消し」を出し、押すと確認ダイアログのあと計測中の記録を削除して、計測前の状態に戻す（記録は残らない）。
- **詳細画面での修正**: 詳細画面（p.5）の睡眠・ワークタブで、記録ごとに開始日時・終了日時を修正、または削除できる【仮: 削除】。終了は開始より後、長さは上の上限以内。修正後は recorded_on と duration_minutes を計算し直す。
- **確定済みの日の記録を修正したとき**【仮】: その日の daily_achievements のスコアは計算し直して表示を変えるが、キャラのポイント（確定済みの増減）は変えない。
- **止め忘れ**: 睡眠は 16 時間、ワークは 12 時間を超えたら、`開始 + 上限` で自動終了扱いにする（次にホーム・記録 API にアクセスしたときに判定）。上限は `config/game.yml`。
- **同時計測**【仮】: 「就寝」を押したときワーク計測中なら、ワークをその時刻で自動終了する。睡眠中は「ワーク開始」を押せない（API は 422）。
- 集計日（`recorded_on`）: 睡眠＝起床した日、ワーク＝開始した日（日本時間）。
- 同じ日に複数の記録があるときは合計する（昼寝・ワークの分割など）。

## 3. 達成度（スコア）とポイント

### 3.1 その日のスコア（0〜100、`daily_achievements.*_score`）
- **食事**: 栄養素ごとに `点 = max(100 − |実際 − 目標| ÷ 目標 × 100, 0)`、`食事スコア = (カロリー点 + たんぱく質点 + 脂質点 + 炭水化物点) ÷ 4`。実際の量はその日の meals の合計。食物繊維は入力・表示・解析・スコアの対象外。
- **睡眠**: `睡眠スコア = min(実際の睡眠時間 ÷ 目標睡眠時間 × 100, 100)`。実際の睡眠時間はその日（recorded_on）の睡眠記録の合計。目標が「時間帯」のときの目標睡眠時間は `起床時刻 − 就寝時刻`（日をまたぐときは +24h）。
- **運動**: `運動スコア = min(その日に達成したタスク数 ÷ 計算時点で有効なタスク数 × 100, 100)`。過去の日も「計算時点で有効なタスク数」を分母にする（タスクを削除した日に 100 を超えないよう頭打ち）。
- **ワーク**: `ワークスコア = 実際のワーク時間 ÷ 目標ワーク時間 × 100`（実際のワーク時間はその日の合計。上限なしで保存。ポイント換算と総合計算では 100 で頭打ち）。
- **今日の総合達成度（%）** = `睡眠×0.30 + 食事×0.30 + 運動×0.20 + ワーク×0.20`（各スコアは 100 で頭打ちにしてから計算）。
- 目標が 0／未設定、タスク 0 件のときはそのスコアを 0 とする（0 除算しない）。

### 3.2 ポイント（翌日に引き継ぐ値、0〜1000、`characters.*_points`）【仮: 換算方法】
- 初期値: 各項目 500、総合 500。
- 日付が変わったら前日分を確定し、項目ごとに `増減 = round((min(スコア,100) − 50) × 2)`、`新ポイント = clamp(旧ポイント + 増減, 0, 1000)`。
  - 100 点で +100、50 点で ±0、記録なし（0 点）で −100。
- 総合ポイント = `round(睡眠pt×0.30 + 食事pt×0.30 + 運動pt×0.20 + ワークpt×0.20)`（最大 1000）。
- 当日分は記録を保存するたびに `daily_achievements` を再計算するだけで、`characters` のポイントは動かさない。
- アプリを開かなかった日: 次にアクセスしたとき、`characters.last_reset_on` の翌日から昨日までを順に確定する（記録のない日はスコア 0）。cron などの定期実行は使わない。`finalized_at` で二重反映を防ぐ。
- **登録した日はポイントに反映しない**: 新規登録時に `last_reset_on = 登録日` とするので、登録日は確定の対象外（ポイント据え置き）。スコアの表示はする。
- 定数（重み 0.30/0.30/0.20/0.20、基準 50、倍率 2、初期 500、上下限 0/1000）は `config/game.yml` に置く。

### 3.3 計算例（テストケースとしても使う）
目標: 睡眠 420分／ワーク 420分／タスク 2件／カロリー 2200・P60・F60・C300。実際: 睡眠 390分／ワーク 300分／タスク 1件達成／1900kcal・P55・F70・C260。前日までのポイント: 睡眠620・食事540・運動410・ワーク580。

| 項目 | スコア | 増減 | 新ポイント |
|---|---|---|---|
| 睡眠 | 92.9 | +86 | 706 |
| 食事 | 87.0（各項目を丸めず平均して小数1桁に丸める） | +74 | 614 |
| 運動 | 50.0 | 0 | 410 |
| ワーク | 71.4 | +43 | 623 |
| 総合 | 今日の総合達成度 78.3% | — | 603 |

### 3.4 ホームでの表示【仮】
- 配置: 上からヘッダー（右に通知ベル＋未読数・メニュー≡）→ キャラ（背景つき）→ **ゲージと吹き出し** → 記録ボタン 6 個 → 下部ナビ。
- 項目ごとのゲージ: **ポイント（0〜1000）** を表示し、横に「今日 xx%」（その日のスコア）を小さく出す。
- 総合: 「総合 603 / 1000 P」。
- 右上の気分バッジ（デザイン p.1 の「元気」）【仮】: 総合ポイントで決める。700 以上「元気」、400〜699「普通」、200〜399「悲しい」、200 未満「怒り」。

## 4. キャラクター
- ユーザー 1 人につき 1 匹（新規登録完了時に作成）。名前は任意（デフォルト「めばえ」）【仮】。
- 状態（`characters.state` enum）と画像（`public/characters/<key>.png`、512×512 透過 PNG）。睡眠不足・満腹・太りは 2026-11-24 になくした（enum の数字 2・3・7 は欠番）:

| key | 表示名 | 画像 |
|---|---|---|
| normal | デフォルト | normal.png |
| sleeping | 睡眠中 | sleeping.png |
| hungry | 空腹 | hungry.png |
| exercising | 汗汗（運動中）。ホームで運動タイマーを動かしている間だけ（4.1） | exercising.png |
| studying | 勉強中 | studying.png |

- 画像は GIF ではなく PNG。動きは CSS アニメーション（ふわふわ上下・睡眠中はゆっくり・汗汗は小刻み）で付ける。`character_animations.gif_path` には `/characters/normal.png` のようなパスを入れる。
- **注意**: `docs/design/` の画面デザインに写っているキャラ画像はモック用。実装では必ず `public/characters/` の画像を使う。

### 4.1 状態の判定（上から順に最初に当てはまったもの）【仮】
判定タイミング: 記録の保存時とホーム表示時（`CharacterStateResolver`）。状態が変わったら `character_state_logs` に記録。
1. 終了していない睡眠記録がある → `sleeping`
2. 終了していないワーク記録がある → `studying`
3. 朝・昼・夕の食事時刻（`goals.breakfast_time` など。初期値 7:00／12:00／19:00）から **1 時間** 過ぎても、その区分の食事記録がない → `hungry`。空腹が続くのは **次の食事時刻まで、またはどれかの食事を記録するまで**。食事時刻が未設定の区分は判定しない
4. それ以外 → `normal`

- `exercising`（汗汗）はサーバーでは判定しない。運動タイマーはブラウザの中だけで動くので、ホームで**タイマーを動かしている間（一時停止中を除く）だけ**汗汗の姿を表示する（ホーム API の `character.exercising` に今の段階の汗汗の画像を入れて返す）。保存された状態・履歴は変えない（2026-11-24。以前の「運動タスクにチェックしてから 30 分」はやめた）

- 日付が変わったら状態はリセット（上の判定をやり直す）。ポイントは引き継ぐ。
- しきい値（食事時刻からの猶予 60分）は `config/game.yml`。

### 4.2 吹き出しメッセージ（ペースメーカー）【仮】
ホーム API が 1 つだけ返す。優先順: 就寝 30 分前〜就寝中でない →「そろそろ寝る時間だよ」（**睡眠目標が「時間帯」のときだけ**。「時間」指定では就寝時刻がないので出さない）／空腹 →「おなかすいた…」／20時以降に未完了タスク →「運動タスクが残ってるよ」／それ以外は状態に合ったひとこと。

### 4.3 キャラの進化（2026-11-10 追加）
目的: 記録を毎日続ける習慣を身につけてもらう。3.2 のポイント（0〜1000、達成度で増減）とは別の **累計ポイント**（`characters.evolution_points`）で、キャラの段階（`evolution_stage`）が決まる。
- **獲得**: 4項目（睡眠・食事・運動・ワーク）のどれかを記録した時点で `100 × その日の継続倍率`（切り捨て）。達成度は見ない。同じ日の同じ項目は1回だけ（4項目で1日最大 400 × 倍率）。
  - 「記録した時点」: 睡眠＝起床、ワーク＝ワーク終了（就寝でワークを自動終了したときを含む）、食事＝記録、運動＝移動距離・運動時間の記録か運動タスクのチェック。止め忘れの自動終了・記録の修正・削除では動かさない（入ったポイントも取り消さない）。
  - 日付は記録の操作をした時刻のユーザーの日付（日本時間 0:00 区切り）。
- **継続倍率** = `1 + 0.1 × 継続日数`（最大 10 倍。1日目 1.1倍、90日目以降 10倍）。継続日数は記録した日（1項目以上）が連続した日数（当日を含む）。計算は 10 分の 1 単位の整数（`100 × (10 + 継続日数) ÷ 10`）。
- **減少**: 記録しなかった日1日につき −200。ログイン後の API への最初のアクセスで、前回記録した日の翌日〜昨日のうち未処理の日数分をまとめて減らし、継続日数を 0 に戻す（今日は数えない。登録日も数えない）。どこまで処理したか（`decay_processed_through`）を保存して二重に減らさない。
- **段階**（累計ポイントの到達ライン）: 0＝0／1＝300／2＝3,000／3＝25,000／4＝150,000／5＝1,000,000（最終）。
- **退化**: 減って今の段階のラインを下回ったら、見合う段階まで一度に下がる。ただし段階1より下には退化しない（段階1以上だった人は 300、段階0の人は 0 で止まる）。
- **通知**: 進化・退化したとき（`notification_type: evolution`。何段階変わっても1件）。
- **ホーム**: ユーザーカードに継続日数、進化カードに 累計ポイント・段階（進化N）・次の段階までのゲージと残りポイント・今日の倍率・今日記録した項目。
- **画像**: `public/characters/stages/<段階>.png`（0＝卵／1＝おしゃぶりの赤ちゃん／2＝笑顔の赤ちゃん／3＝芽／4＝つぼみ。2026-11-10 チームの画像）。段階5は画像ができるまで 4.png。探す順は `stages/<段階>_<状態>.png` → `stages/<段階>.png` → 下の段階の画像 → 状態の画像（4章の表）。段階の姿が状態の画像より優先。段階1〜4には `hungry`・`exercising`・`sleeping`・`studying` の状態別の絵がある（2026-11-24）。段階の絵が状態を表していないとき（`<段階>_<状態>.png` がないとき）は、ホームのキャラの右上に状態のマーク（線画のアイコン＋「空腹」などの状態名）を重ねる。CSS の動きと夜の部屋はこれまでどおり。
- **演出**: ホームを読み直して段階が変わっていたら、キャラを光らせて（退化は揺らして）「進化した！」のお知らせを出す。
- **テスト（開発用）**: `npm run dev` のときだけ、ホーム右上に「テスト」ボタンが出る。記録・日を進める・毎日記録して進める・段階を選ぶ・直接決める・リセットを試せる（API は `/api/v1/dev/evolution`、development・test だけ。本番のビルド・ルートには入らない）。
- 定数（100・倍率・−200・段階のライン・下限の段階）は `config/game.yml` の `evolution`、計算は `app/services/evolution_rules.rb`。

| 相互フォローの人の詳細【仮】 | なし | 自分の「詳細」と同じ内容（スコアとポイントの推移・就寝と起床の時刻・ワークの内容・日ごとの栄養の合計・移動距離）を**読み取り専用**で見る。食事の内容・写真・メモは見せない（2026-10-07 チームの要望） |
| 通知 | なし | 新しい順の一覧、未読は強調、開いたら既読。ヘッダーにベル＋未読バッジ【仮】 |
| 設定 | p.15 | プロフィール変更／目標の設定／ログアウト |

- 睡眠（p.6）・ワーク（p.7）の画面は **作らない**（記録はホームのボタンだけ）。
- 新規登録の流れ【仮】: ①〜④の入力はフロントで保持し、最後に `POST /auth` → `PUT /goal` の順で送信する（users.name / birthdate が NOT NULL のため、①の時点でユーザーを作らない）。①ではメールの重複だけ API で確認する。
- **目標が未登録のユーザー**（`PUT /goal` が失敗した場合など）は、ログイン後にホームではなく目標設定画面へ誘導する。

## 6. 食事の入力（ミールスキャン）【仮】
- 今回は **手入力** で実装（`input_method: manual`）。写真は Active Storage で保存して表示するだけ。
- 「撮影する」はスマホのカメラ／ファイル選択（`<input type="file" accept="image/*" capture="environment">`）。
- 写真から料理名・栄養値を出す「スキャン」は後回し。`app/services/meal_scanner.rb` にインターフェースだけ用意し（今は `nil` を返す）、使う API（費用・API キーの管理を含む）を決めてから実装する。

## 7. 通知【仮】
- 種類: follow（フォローされた）／character（キャラの状態変化: 空腹）／reminder（就寝時刻）／task（20時以降の未完了タスク）／evolution（キャラの進化・退化。4.3）。
- 作るタイミング: フォロー時、ホーム表示時の判定で。
- 回数の制限: **follow は制限なし**（フォローされるたびに作る）。**character（空腹）は 1 日 1 回**（睡眠不足の通知は 2026-11-24 になくした）。reminder・task は 1 日 1 回。
- プッシュ通知・メールは作らない（アプリ内のみ）。

### 新規登録の入力仕様（2026-11-17 更新）
- プロフィールはユーザー名・生年月日・身長（cm）・体重（kg）・性別が必須。性別の選択肢は男性・女性。身長・体重は0より大きく1000未満の数値を保存する。
- 入力エラーは該当項目の直下に表示する。登録APIは従来のerrors配列に加えてfield_errorsを返す。
- 食事目標の初期値は日本時間の満年齢と性別で年齢区分を選ぶ。1〜17歳にも2025年版の該当区分を使い、1歳未満や該当基準がない場合は成人値を代用しない。

### 食事区分・登録件数（2026-11-17 更新）
- 朝食・昼食・夕食は日本時間の食事日ごとに各1件まで。追加したい食品は既存の食事を編集する。間食は複数件登録可能。
- 区分は入力した「食べた時刻」から自動決定し、手動では選択しない。本人の目標時刻（未設定なら7:00／12:00／19:00）の前後1時間以内で最も近い食事とし、それ以外は間食とする。登録・編集ともサーバーで判定する。

### 写真の栄養推定と精度評価（2026-11-17 更新）
- 内容欄の編集のみでは栄養値を変更しない。写真の再解析は「再解析する」で明示的に実行する。写真選択前に入力した内容も解析ヒントに使う。
- 店舗別の特例を使わず、品目ごとの調理後重量と100gあたりの栄養値から計算する。食品成分表候補に一致する食品・調理状態は登録値を使い、それ以外はAIの推定値と区別する。推定量は画面で修正・再計算できる。評価方法はdocs/meal_scan_accuracy.mdを参照。
- PFCとカロリーの大きな不整合があるAI推定は栄養値を自動入力せず案内する。整合性確認は精度の保証にはならず、実際の写真と既知の栄養値での比較を必要とする。

### 活動量・AI食事目標（2026-11-18 更新）
普段の活動量を三択で入力・保存する。食事目標は身長・体重・満年齢・性別・活動量で算出し、新規登録の食事目標画面を開くとAIの提案を自動入力する。数値は手動調整可能。AI失敗時は計算式の値へ戻す。対象範囲・基準と算出方法はdocs/nutrition_targets.mdを参照。
