# 仕様書 — 生活リズム改善ゲーム（sotuken_b）

> 版: 2026-10-06 たたき台（同日 チーム回答を反映）。【仮】の付いた項目はチーム未決定の仮決め。決まったらこのファイルを直接書き換える。
> DB の詳細は `docs/db_design.md`、画面の見た目は `docs/design/screen_pXX.png`（XX＝画面デザイン資料のページ番号）。

## 1. 目的と概要
- 目的: 自分の生活リズムを整える。
- 概要: キャラの状態に合わせることで自分の生活リズムを整えるゲーム。まず理想の生活リズムを登録する。キャラは一日の中で、登録された生活リズムどおりに生活する。ユーザーの記録が目標からずれるとキャラの状態が変わり（例: 睡眠が短い → 睡眠不足になり、寝ることを勧める）、ユーザーはキャラに合わせて生活するようになる。
- キャラの役割【仮】: 次の 2 つを両方持たせる。
  1. **鏡**: ユーザーの記録・計測中のタイマーを反映して状態が変わる（睡眠中・勉強中・汗汗・空腹・睡眠不足など）。
  2. **ペースメーカー**: 目標の時刻（就寝・食事）が近づく／過ぎると、ホームの吹き出しで行動を促す（例:「そろそろ寝る時間だよ」）。状態そのものは変えない。

## 2. 記録する項目（設定項目）
| # | 項目 | 目標の設定 | 記録のしかた |
|---|---|---|---|
| 1 | 睡眠 | 「時間」（例 7時間）または「時間帯」（例 0:00〜7:00）を選んで設定 | ホームの「就寝」ボタンを押すと開始し、ボタンが「起床」に変わる。「起床」を押すと終了し、`睡眠時間 = 起床日時 − 就寝日時` で計算する。**睡眠専用の画面・手動入力はない** |
| 2 | 食事 | カロリー・たんぱく質・脂質・炭水化物・食物繊維の 1 日目標。初期値は年齢・性別から自動設定（`nutrition_standards`。性別が未回答・その他のときは男女の平均値）。食事時刻（朝・昼・夕）は初期値 **7:00／12:00／19:00**、目標変更画面で変更できる | 1 食ずつ記録（内容・区分・時間・栄養値・写真・コメント） |
| 3 | 運動 | やることをタスクとして複数登録（例: 1キロ走る／腕立て100回）。1 件以上必須【仮】 | 運動画面のチェックリストで毎日チェック。任意で移動距離を手入力。**運動タイマーはない** |
| 4 | ワーク | 1 日の目標ワーク時間（画面上の「学習時間」） | ホームの「ワーク開始」ボタンを押すと開始し、ボタンが「ワーク終了」に変わる。「ワーク終了」を押すと終了し、時間を計算する。**ワーク専用の画面・手動入力はない** |
| 5 | 自由設定（入浴・趣味など） | **今回の範囲外【仮】**（DB設計書で保留）。ホームのボタンは表示するが「準備中」 | — |

用語の統一: 画面・コードでは「ワーク」に統一する（画面資料の「仕事」「学習時間」「学習」タブも同じものを指す）。キャラ状態名は「勉強中」のまま。運動の目標欄の見出しは「運動」（資料の「運動時間」ではない）。

### 2.1 睡眠・ワークのタイマーの決まり
- 開始日時・終了日時はサーバーの時刻で保存する（ページを閉じても計測は続く）。
- **押し間違いの取り消し（強制リセット）**: 計測中はホームに「取り消し」を出し、押すと確認ダイアログのあと計測中の記録を削除して、計測前の状態に戻す（記録は残らない）。
- **詳細画面での修正**: 詳細画面（p.5）の睡眠・ワークタブで、記録ごとに開始日時・終了日時を修正、または削除できる【仮: 削除】。終了は開始より後、長さは上の上限以内。修正後は recorded_on と duration_minutes を計算し直す。
- **確定済みの日の記録を修正したとき**【仮】: その日の daily_achievements のスコアは計算し直して表示を変えるが、キャラのポイント（確定済みの増減）は変えない。
- **止め忘れ**: 睡眠は 16 時間、ワークは 12 時間を超えたら、`開始 + 上限` で自動終了扱いにする（次にホーム・記録 API にアクセスしたときに判定）。上限は `config/game.yml`。
- **同時計測**【仮】: 「就寝」を押したときワーク計測中なら、ワークをその時刻で自動終了する。睡眠中は「ワーク開始」を押せない（API は 422）。
- 集計日（`recorded_on`）: 睡眠＝起床した日、ワーク＝開始した日（日本時間）。
- 同じ日に複数の記録があるときは合計する（昼寝・ワークの分割など）。

## 3. 達成度（スコア）とポイント

### 3.1 その日のスコア（0〜100、`daily_achievements.*_score`）
- **食事**: 栄養素ごとに `点 = max(100 − |実際 − 目標| ÷ 目標 × 100, 0)`、`食事スコア = (カロリー点 + たんぱく質点 + 脂質点 + 炭水化物点 + 食物繊維点) ÷ 5`。実際の量はその日の meals の合計。
- **睡眠**: `睡眠スコア = min(実際の睡眠時間 ÷ 目標睡眠時間 × 100, 100)`。実際の睡眠時間はその日（recorded_on）の睡眠記録の合計。目標が「時間帯」のときの目標睡眠時間は `起床時刻 − 就寝時刻`（日をまたぐときは +24h）。
- **運動**: `運動スコア = min(その日に達成したタスク数 ÷ 計算時点で有効なタスク数 × 100, 100)`。過去の日も「計算時点で有効なタスク数」を分母にする（タスクを削除した日に 100 を超えないよう頭打ち）。
- **ワーク**: `ワークスコア = 実際のワーク時間 ÷ 目標ワーク時間 × 100`（実際のワーク時間はその日の合計。上限なしで保存。ポイント換算と総合計算では 100 で頭打ち）。
- **今日の総合達成度（%）** = `睡眠×0.30 + 食事×0.30 + 運動×0.20 + ワーク×0.20`（各スコアは 100 で頭打ちにしてから計算）。
- 目標が 0／未設定、タスク 0 件のときはそのスコアを 0 とする（0 除算しない）。

### 3.2 ポイント（翌日に引き継ぐ値、0〜1000、`characters.*_points`）【仮: 換算方法】
- 初期値: 各項目 500、総合 500。
- 日付が変わったら前日分を確定し、項目ごとに `増減 = round((min(スコア,100) − 50) × 2)`、`新ポイント = clamp(旧ポイント + 増減, 0, 1000)`。
  - 100 点で +100、50 点で ±0、記録なし（0 点）で −100。
- 総合ポイント = `round(睡眠pt×0.30 + 食事pt×0.30 + 運動pt×0.20 + ワークpt×0.20)`（最大 1000）。
- 当日分は記録を保存するたびに `daily_achievements` を再計算するだけで、`characters` のポイントは動かさない。
- アプリを開かなかった日: 次にアクセスしたとき、`characters.last_reset_on` の翌日から昨日までを順に確定する（記録のない日はスコア 0）。cron などの定期実行は使わない。`finalized_at` で二重反映を防ぐ。
- **登録した日はポイントに反映しない**: 新規登録時に `last_reset_on = 登録日` とするので、登録日は確定の対象外（ポイント据え置き）。スコアの表示はする。
- 定数（重み 0.30/0.30/0.20/0.20、基準 50、倍率 2、初期 500、上下限 0/1000）は `config/game.yml` に置く。

### 3.3 計算例（テストケースとしても使う）
目標: 睡眠 420分／ワーク 420分／タスク 2件／カロリー 2200・P60・F60・C300・食物繊維21。実際: 睡眠 390分／ワーク 300分／タスク 1件達成／1900kcal・P55・F70・C260・繊維12。前日までのポイント: 睡眠620・食事540・運動410・ワーク580。

| 項目 | スコア | 増減 | 新ポイント |
|---|---|---|---|
| 睡眠 | 92.9 | +86 | 706 |
| 食事 | 81.0（86.4/91.7/83.3/86.7/57.1 の平均） | +62 | 602 |
| 運動 | 50.0 | 0 | 410 |
| ワーク | 71.4 | +43 | 623 |
| 総合 | 今日の総合達成度 76.5% | — | 599 |

### 3.4 ホームでの表示【仮】
- 配置: 上からヘッダー（右に通知ベル＋未読数・メニュー≡）→ キャラ（背景つき）→ **ゲージと吹き出し** → 記録ボタン 6 個 → 下部ナビ。
- 項目ごとのゲージ: **ポイント（0〜1000）** を表示し、横に「今日 xx%」（その日のスコア）を小さく出す。
- 総合: 「総合 599 / 1000 P」。
- 右上の気分バッジ（デザイン p.1 の「元気」）【仮】: 総合ポイントで決める。700 以上「元気」、400〜699「普通」、200〜399「悲しい」、200 未満「怒り」。

## 4. キャラクター
- ユーザー 1 人につき 1 匹（新規登録完了時に作成）。名前は任意（デフォルト「めばえ」）【仮】。
- 状態（`characters.state` enum）と画像（`public/characters/<key>.png`、512×512 透過 PNG）:

| key | 表示名 | 画像 |
|---|---|---|
| normal | デフォルト | normal.png |
| sleeping | 睡眠中 | sleeping.png |
| sleep_deprived | 睡眠不足 | sleep_deprived.png |
| full | 満腹 | full.png |
| hungry | 空腹 | hungry.png |
| exercising | 汗汗（運動中） | exercising.png |
| studying | 勉強中 | studying.png |
| fat | 太り（運動不足）【仮: 要件は 7 状態。DB 設計で 8 つめとして追加。不採用なら normal 扱い】 | fat.png |

- 画像は GIF ではなく PNG。動きは CSS アニメーション（ふわふわ上下・睡眠中はゆっくり・汗汗は小刻み）で付ける。`character_animations.gif_path` には `/characters/normal.png` のようなパスを入れる。
- **注意**: `docs/design/` の画面デザインに写っているキャラ画像はモック用。実装では必ず `public/characters/` の画像を使う。

### 4.1 状態の判定（上から順に最初に当てはまったもの）【仮】
判定タイミング: 記録の保存時とホーム表示時（`CharacterStateResolver`）。状態が変わったら `character_state_logs` に記録。
1. 終了していない睡眠記録がある → `sleeping`
2. 運動タスクにチェックを付けてから 30 分以内【仮: 運動タイマーをなくしたため】 → `exercising`
3. 終了していないワーク記録がある → `studying`
4. 食事記録から 90 分以内 → `full`
5. 朝・昼・夕の食事時刻（`goals.breakfast_time` など。初期値 7:00／12:00／19:00）から **1 時間** 過ぎても、その区分の食事記録がない → `hungry`。空腹が続くのは **次の食事時刻まで、またはどれかの食事を記録するまで**。食事時刻が未設定の区分は判定しない
6. 今日の睡眠スコアが 80 未満（起床済み） → `sleep_deprived`
7. 運動ポイントが 300 未満 → `fat`
8. それ以外 → `normal`

- 日付が変わったら状態はリセット（上の判定をやり直す）。ポイントは引き継ぐ。
- しきい値（運動後 30分・食後 90分・食事時刻からの猶予 60分・睡眠スコア 80・運動ポイント 300）は `config/game.yml`。

### 4.2 吹き出しメッセージ（ペースメーカー）【仮】
ホーム API が 1 つだけ返す。優先順: 就寝 30 分前〜就寝中でない →「そろそろ寝る時間だよ」（**睡眠目標が「時間帯」のときだけ**。「時間」指定では就寝時刻がないので出さない）／睡眠不足 →「ねむい…今日は早く寝よう」／空腹 →「おなかすいた…」／20時以降に未完了タスク →「運動タスクが残ってるよ」／それ以外は状態に合ったひとこと。

## 6. 食事の入力（ミールスキャン）【仮】
- 今回は **手入力** で実装（`input_method: manual`）。写真は Active Storage で保存して表示するだけ。
- 「撮影する」はスマホのカメラ／ファイル選択（`<input type="file" accept="image/*" capture="environment">`）。
- 写真から料理名・栄養値を出す「スキャン」は後回し。`app/services/meal_scanner.rb` にインターフェースだけ用意し（今は `nil` を返す）、使う API（費用・API キーの管理を含む）を決めてから実装する。

## 7. 通知【仮】
- 種類: follow（フォローされた）／character（キャラの状態変化: 睡眠不足・空腹）／reminder（就寝時刻）／task（20時以降の未完了タスク）。
- 作るタイミング: フォロー時、ホーム表示時の判定で。
- 回数の制限: **follow は制限なし**（フォローされるたびに作る）。**character は状態ごとに 1 日 1 回**（睡眠不足と空腹は別々に数える）。reminder・task は 1 日 1 回。
- プッシュ通知・メールは作らない（アプリ内のみ）。
